## 三、功能缺口（不齐全/有偏差）

### 1. 督办状态流转（`supervise`）
后台 `enhance_routes.py` 已提供 `POST /supervise/<sid>/status`（支持 `assigned / in_progress / done / rejected`，管理端 `manage_routes.py` 也有一份），但小程序 `supervise.js` 只实现了**派单**，没有对督办任务进行「处理中/完成/驳回」状态流转的操作入口。

**缺失**：督办任务状态操作按钮（绑定 `POST /supervise/<sid>/status`）。

### 2. 工作报告（`report`）
后台 `/report` 是**服务端按日期聚合**（任务、检查、隐患、台账、验收、快检、抽考、照片墙等全模块统计），字段丰富（`tasksCreated / inspections / hazardsClosed / ledger / acceptance / spotChecks / quizRecords`）。

小程序 `report.js` 是**前端手动过滤**，只用 `/tasks` 和 `/hazards` 两个接口，且按 `due_date`（不是 `created_at`）过滤，统计口径与后台不一致，且未覆盖验收/快检/抽考/台账等模块。

**缺失**：调用 `/report` 接口，展示完整日报统计；修正按创建日期统计。

### 3. 照片墙删除
后台有 `DELETE /photos/<id>`，小程序照片墙未提供删除操作（照片上传方也缺少删除入口）。属管理侧能力，优先级低。

### 4. 隐患督办与照片的关联
后台 `fs_photos` 带 `site_id / unit_id / building_id / place_id` 组织维度，小程序上传照片时未传这些维度（`bizType='hazard'` 时只传 `dataUrl/caption/bizId`），导致照片墙按单位/建筑/部位筛选时数据不全。

### 5. 权限模块动态下发
首页 `MODULES` 依赖 `/me` 返回的 `modules` 字段来过滤入口，依赖后台角色映射。需确认后台 `/me` 已为各角色正确返回这些模块 key（含 `emg/equip/board/report` 等），否则入口不显示。

## 四、结论

小程序**主流程（任务→检查→隐患→闭环）完整闭环**，13 个核心模块均已落地并与后台打通。主要缺口集中在两处：

1. **督办状态流转**（功能不完整，需补处理/完成/驳回操作）
2. **工作报告**（统计口径不对、未用后台 `/report`、覆盖不全）

其余如照片墙删除、照片组织维度、督办关联，属于完善项。
